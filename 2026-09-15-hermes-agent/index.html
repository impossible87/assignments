    02
    What it is

    先用一分钟搞清楚它是什么

    不然很容易把它当成"又一个 AI 聊天框"，那样就白装了。

    Hermes Agent 是 Nous Research 开源的自主 agent，MIT 许可，用 Python 写。[8][11] 它不是补全插件，也不是套壳聊天框，而是一个常驻的、能自己动手干活的程序：你给它任务，它会调用工具（跑命令、读写文件、开浏览器、搜索）一步步做完，而且做完之后会记住。

    换个说法

    普通 AI 助手像每天失忆的客服：每次都要重新解释你是谁、要什么。Hermes 像跟你干了半年的助理：他知道你的项目在哪、你的习惯是什么，而且会把做过的事写成操作手册，下次同类任务直接照做。

    它和 Claude Code / Codex 的关系

    同一类产品（工具调用型 agent），差别在三点：跑在哪（它可以常驻你的 VPS 或 serverless，从 Telegram 指挥）、用哪个模型（20+ 提供商随时切）、会不会自己长（记忆与技能是第一等公民）。[1][8]

    03
    Installation

    第一步：装好它

    选对系统拿命令，装完立刻自检。

    —

    装完必须做的两件事

    1. CHECK 01

      重载 shell

      source ~/.bashrc（zsh 用户改成 ~/.zshrc），让 hermes 命令进 PATH。Windows 重开一个 PowerShell 窗口即可。

    2. CHECK 02

      跑一次体检

      hermes doctor。它会检查依赖、配置、模型连通性。这一步没过就别往下走 —— 后面所有问题都会变得更难查。

    平台支持分级

    平台 / 架构安装方式级别说明

    Tier 1 = 官方优先保证不被破坏；Tier 2 = 尽力维护、可能随版本损坏；不支持 = 不接受相关修复。来源 [3]。

    三个新手最容易踩的坑

    ① 不要用 pip 装。官方把 pip install hermes-agent、uv tool install、brew install 明确列为不支持，而网上大量教程还在教这个。② Docker 装完不能自更新。容器里没有 hermes update，升级要拉新镜像。③ macOS Intel 不支持。桌面安装包只面向 Apple Silicon。[3]

    安装器到底帮你装了什么？（以及装在哪）

    你只需要系统里有 git；Linux 上再确认 curl 和 xz-utils（sudo apt install curl xz-utils）；要装桌面端再加 build-essential。其余全自动：uv、Python 3.11、Node.js、ripgrep、ffmpeg。[2]

    安装方式代码位置命令位置数据目录
    普通用户~/.hermes/hermes-agent/~/.local/bin/hermes~/.hermes/
    root 模式/usr/local/lib/hermes-agent//usr/local/bin/hermes/root/.hermes/

    数据目录里放的是认证、记忆、技能、会话 —— 装之前先知道它在哪里，将来备份才找得到。

    没有 sudo 权限 / 想当系统服务跑
    整条安装路径里只有 Playwright 装 Chromium 系统依赖需要 root。做法：管理员先跑一次 sudo npx playwright install-deps chromium，然后由服务用户自己跑安装脚本，安装器检测到没有 sudo 会自动跳过依赖步骤、把 Chromium 装进用户自己的缓存。完全不需要浏览器自动化就加 --skip-browser。[2]
    想换台机器、或者彻底卸载
    迁移用 hermes backup（完整备份，含凭据）或 hermes profile export（只导出单个 agent，按设计不含凭据），在新机器上 hermes import 恢复。卸载按系统区分：Linux 用 systemctl --user disable hermes-gateway，macOS 用 launchctl remove ai.hermes.gateway。[2]
    04
    Model setup

    第二步：配一个模型

    这是整个设置里最重要的一步。选你能拿到的那个提供商，照着填。

    先搞懂四个概念的关系

    这一步的关键是理解 Provider、Model、Base URL、API Key 四者的关系，其实一张图就够：Provider 是供应商，Model 是具体型号，API Key 是你的身份，Base URL 是请求发到哪台服务器。前两个决定"用谁"，后两个决定"怎么连上"。

    模型名一律写成 提供商/型号，这是新手最容易写错的地方。

    要接第三方或自建的 API 怎么办

    用"自定义端点"：先 hermes model 选择对应提供商（或通用 OpenAI 兼容项），再把三样东西填进去 —— Base URL（别人给你的地址）、API Key、模型名。填完务必用 hermes config get model 确认生效，再跑一句话验证连通。密钥只写进 ~/.hermes/.env。

    三种初始化方式，新手直接选第一种

    推荐

    Quick Setup（Nous Portal）

    一次 OAuth 登录，模型和工具网关（网页搜索、图像生成、TTS、云浏览器）一起配好，不用管 API key。hermes setup --portal

    自带 key

    Full Setup

    自己走一遍提供商、工具、模型选项。适合已经有 API key、或者要用自己的额度。

    最小化

    Blank Slate

    除了模型、文件操作和终端以外全部关掉：没有网络、浏览器、记忆、技能、MCP。适合想完全自己控制的人。

    三种模式来自官方 Quickstart 与安装页。[4][2]

    选一个提供商，拿配置方法

    —

    配置放在哪：一条规则就够了

    密钥进 .env，其他进 config.yaml

    API key、bot token、密码这类机密放 ~/.hermes/.env；模型名、终端后端、压缩设置、记忆上限这类非机密放 ~/.hermes/config.yaml。hermes config set 会自动把值写到正确的文件，不用你判断。[12]

    10
    Hands-on tool calling

    让它干一件真事：读文件 → 处理 → 写结果

    这一节的目标是"完成一次读取文件、处理数据并生成结果文件的 Tool Calling"，照下面三步做。

    1. STEP 01

      准备一个小数据文件

      在任意目录建 sales.csv，随便写几行"类别,金额"，例如 硬件,1200。

    2. STEP 02

      用一句话下任务

      启动 hermes，说："读取当前目录的 sales.csv，按类别汇总金额，把结果写到 summary.md"。不要手把手教步骤。

    3. STEP 03

      观察并验收

      你会看到它连续调用 文件读取 → 代码执行（或终端）→ 文件写入 三类工具；结束后用 ls 确认 summary.md 生成，打开核对数字对不对。

    涉及的工具集来自官方工具文档：file、terminal、code_execution 默认可用。[18]

    三个常见失败原因

    ① 模型不支持工具调用（选了纯聊天模型）→ 换一个支持 tool calling 的模型；② 工具集被关掉→ 用 hermes tools 检查 file / terminal 是否启用；③ 工作目录不对 → 它是在当前目录找文件，先 cd 到数据所在目录再启动。

    06
    Skills

    第四步：用技能，并让它自己长技能

    技能是 Hermes 最值得体验的部分：它不是提示词模板，而是"按需加载的操作手册"。

    每个已安装的技能都会自动变成一个斜杠命令。在 CLI 或任何消息平台里直接敲就行：[6]

    /github-pr-workflow 给 auth 重构开一个 PR
/excalidraw                      # 只写技能名，它会先加载再问你要做什么
    一个很多人不知道的用法：叠加技能

    一条消息开头最多可以链式写 5 个技能，剩下的内容当作指令。比如 /github-pr-workflow /test-driven-development 修复 #123 并开 PR。解析在第一个不是技能名的词处停止，所以像 /tmp/scan.pdf 这样的路径参数不会被误吞。[6]

    怎么"让它自己学"

    1. 01

      先给一个完整任务

      比如"把这份日志按服务归类并生成周报"。它会在多轮工具调用中自己摸索出流程。

    2. 02

      任务结束后去翻目录

      复杂任务之后，它会把可复用的流程写成技能，落在 ~/.hermes/skills/。这一步是它自己做的，不需要你下指令。

    3. 03

      下次直接复用

      同类任务再说一次，它会直接调用已有技能，前面那些试错不再发生。

    4. 04

      不满意就改

      技能是纯文本文件，你可以直接编辑；也可以让它自己改 —— agent 有权修改或删除任何技能。

    你想做的事命令 / 做法
    问它"你有哪些技能"hermes chat --toolsets skills -q "What skills do you have?"
    不想预装官方技能安装时加 --no-skills，或 hermes skills opt-out
    连未修改的官方技能一起删掉hermes skills opt-out --remove（会二次确认；你改过的技能永远保留）
    反悔，重新装回官方技能hermes skills opt-in --sync
    挂载外部技能目录在配置里指向额外目录，与本地技能目录并列扫描

    技能目录是 ~/.hermes/skills/，兼容 agentskills.io 开放标准。[6]

    07
    Memory

    第五步：把记忆管好，别让它变成"死记忆"

    记忆是这个产品的卖点，也是新手最容易管坏的地方。这一节讲三件事：怎么记、怎么保鲜、怎么不丢。

    ① 它是怎么记的

    内置记忆就是两个纯文本文件，都有硬性字符上限：[7]

    两个文件都在 ~/.hermes/memories/，在每次会话开始时作为一个"冻结快照"注入系统提示 —— 也就是说它不会中途变化，这保证了同一轮对话里的行为一致。

    关键机制：记忆满了不会静默丢，而是报错

    写入超过上限时，memory 工具直接返回错误，agent 必须在同一轮里自己整理 —— 合并、精简或删除条目 —— 然后再重试。这是"记忆不会腐烂"的第一道保障：系统逼它保持精炼，而不是无限堆积。[7]

    ② 什么样的记忆会"死掉"，怎么救

    症状为什么会这样怎么处理
    记忆里全是过期信息（旧路径、旧项目、旧偏好），占满额度它只会在写满时才整理，平时不会主动清理直接说"检查一下你的记忆，删掉已经过期的条目"，或自己打开 ~/.hermes/memories/*.md 手动清
    它记错了你、行为变得奇怪两个 agent 进程指向了同一个 Hermes 主目录，互相把对方的写入叠进自己的状态一个 agent 一个 profile。hermes profile create 名字，各自的记忆、技能、会话完全隔离
    换了电脑 / 重装系统之后记忆全没了记忆只在本地磁盘上定期 hermes backup；换机器用 hermes import 恢复
    记忆额度太小，重要的东西记不下内置记忆有硬上限（2,200 + 1,375 字符）挂一个外部记忆提供商（见下），内置记忆仍然并行工作

    ③ 要记得更多：外部记忆提供商

    官方内置了 8 个外部记忆提供商插件，用来承载超出 MEMORY.md / USER.md 的长期知识：openviking、honcho、mem0、hindsight、holographic、retaindb、byterover、supermemory。同一时间只能启用一个，而内置记忆始终并行工作。[13]

    hermes memory setup     # 交互式选择和配置外部记忆提供商
hermes memory status    # 看当前启用的是哪个
hermes memory off       # 关掉外部提供商，回到只用内置记忆

    ④ 备份：记忆的第二条命

    命令包含什么用在哪
    hermes backup完整备份，包含凭据换机器、重装、定期冷备
    hermes profile export单个 agent，按设计不含凭据把某个 agent 单独搬走或分享
    hermes import用备份恢复在新机器上还原

    注意：profile 导出不等于备份 —— 它故意不含密钥。[2]

    ⑤ 还有一层：会话检索

    除了上面这些"提炼过的记忆"，所有历史会话都存在本地 SQLite 里，并用 FTS5 全文检索 + LLM 摘要做跨会话召回。所以即使某件事没被写进 MEMORY.md，它也能翻出当初的对话。[5][8]

    08
    MCP

    第六步：接 MCP，把外部工具借进来

    MCP 是"让 agent 用上别人已经写好的工具"的标准做法。

    MCP（Model Context Protocol）让 Hermes 连接外部的工具服务器 —— GitHub、数据库、文件系统、内部 API 都行。你不需要先写一个 Hermes 原生工具，只要把服务器挂上去，它会在启动时自动发现并注册工具。[9]

    三步接好一个 MCP 服务器

    1. STEP 01

      确认能力已内置

      MCP 支持随标准安装一起进来，不需要额外装东西。

    2. STEP 02

      写进 config.yaml

      在 ~/.hermes/config.yaml 里加一段 mcp_servers，本地 stdio 和远程 HTTP 服务器可以写在一起。

    3. STEP 03

      重启对话并验收

      启动 hermes chat，直接让它用那个能力，例如"列出 /home/user/projects 里的文件并总结仓库结构"。

    # ~/.hermes/config.yaml
mcp_servers:
  filesystem:
    command: "npx"
    args: ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]
    两个实用细节

    按服务器过滤工具：可以只暴露你真正想让 agent 看到的那些 MCP 工具，而不是把整个服务器的能力全放开。从 Claude Code 迁过来：你原来的 ~/.claude.json 里的 mcpServers 对应 Hermes 的 mcp_servers，一条 hermes import-agent claude-code 可以把 MCP 配置连同技能和指令一起迁过来。[9]

    另外，MCP 子进程的环境变量是隔离的（凭据过滤），这是官方八层安全模型中的一层。[10]

    一个 gateway 后台进程，同时连上你配置的所有平台，负责会话、定时任务和语音消息投递。配置入口就一条命令：hermes gateway setup。[14]

    平台语音图片文件话题表情回应流式输出
    Telegram✓✓✓✓—✓
    Discord✓✓✓✓✓✓
    Slack✓✓✓✓✓✓
    WhatsApp—✓✓——✓

    还有飞书 / Lark、企业微信、微信、钉钉、QQ、Teams、Matrix、Mattermost、Signal、短信、邮件、Home Assistant 等。[14]

    新手提醒

    机器人要正常工作，需要模型提供商和工具提供商都有（比如搜索、TTS）。如果你用的是 Nous Portal 订阅，这一步是打包好的；自己配 key 的话要记得把工具对应的 key 也加上，否则会出现"它能回复但什么也做不了"的情况。

    顺带一提：定时任务
    内置 cron 调度器，用自然语言描述任务，结果可以投递到任意已连接平台 —— 每天早报、每周巡检、夜间备份都可以无人值守跑。[8]
    10
    Security

    安全：让它能干活的边界在哪

    让一个程序在你机器上跑命令，安全问题必须先想清楚。官方给了八层防护。

    防护层它防什么

    来源 [10]。八层是官方安全页自己的划分，下面挑三件新手最该动手的事展开。

    ① 危险命令审批：三种模式

    执行任何命令前，Hermes 会先用一份危险模式清单做检查，命中就要你明确批准。审批策略写在 ~/.hermes/config.yaml 里：[10]

    模式行为适合谁
    smart（默认）只对命中危险清单的命令要求批准绝大多数人，别改
    manual每一步都要你点头第一次跑、或让它碰生产环境
    off不询问，直接执行只在完全隔离的容器里用
     
    # ~/.hermes/config.yaml
approvals:
  mode: smart              # smart | manual | off
  timeout: 300             # 等你回复的秒数
  cron_mode: deny          # 定时任务命中危险命令时：默认拒绝，而不是自动批准
  single_query_mode: deny  # 一次性 -q 会话同理
  unattended_mode: deny    # webhook / API 这类无人值守入口同理

    注意无人值守场景的默认值都是 deny：宁可让 agent 另想办法，也不在没有人的时候自动批准危险操作。

    ② 三个系统各自要注意什么

    Windows 10 / 11

    用官方安装脚本

    Tier 1 支持，但官方说明有少数功能不可用。别用第三方教程里的 pip/conda 路径。原生 PowerShell 安装后重开窗口再跑 hermes doctor。

    macOS

    只支持 Apple Silicon

    Intel Mac 不在支持范围。首次运行若被系统拦权限（文件、屏幕录制、麦克风），到"系统设置 → 隐私与安全性"里按提示授权。

    Linux / WSL2

    别用 root 跑日常

    用普通用户安装即可。要当系统服务跑，按官方做法建一个专用非特权用户，只在装 Chromium 系统依赖时用一次 sudo。

    ③ 想更隔离：用容器后端

    把终端后端切成 docker，每条命令都在容器里执行。官方对每个容器强制加了一组加固参数：丢光所有 Linux capabilities 再按需加回三个、禁止提权、限制进程数 256、/tmp 与 /var/tmp 单独挂载并限制大小（/var/tmp 还禁止执行）。资源上限可在配置里调。[10]

    hermes config set terminal.backend docker   # 让所有命令在容器里跑
    三条自己给自己定的规矩

    密钥只进 .env，不要贴进对话、不要提交到 Git 仓库；别把两个 agent 指向同一个 Hermes 主目录（会互相污染记忆，用 profile 隔离）；第一次跑陌生技能或 MCP 服务器时用 manual 审批模式，看清楚它到底要执行什么。

    13
    Learning loop

    为什么"第二次会更快"

    把上面前几节串起来看，就是它的学习循环。

    举个例子

    你让它"把服务器日志按服务归类并生成周报"。第一次它要自己摸索日志目录、试错字段格式、确认时间区间，来回十几轮，花掉不少 token。任务结束后它把这一整套流程沉淀成技能。第二次你说同样的话，它直接调用那个技能 —— 前面那些试错不再发生。差别不在模型，而在"有没有把过程留下来"。

    Where it runs

    跑在哪、花多少钱

    形态 01

    最省事，适合先跑通。装完即用，不产生额外机器成本。

    形态 02

    常驻 VPS

    形态 03

    Modal、Daytona 这类按需启动的后端，闲置时几乎不产生费用。[8]

    形态 04

    Docker / SSH / Singularity

    用于隔离或连接远程机器，容器后端自带上面那套加固参数。[5][10]

    成本怎么算

    软件本身 MIT 免费，官方没有公开定价表，所以这里不给具体金额。真实成本 = 机器的钱（自己电脑 0、VPS 按月、serverless 按运行时间）+ 模型的 token 费（自备 API key，或用 Nous Portal 订阅覆盖 300+ 模型与工具网关）。要估算只能按你自己的任务量算，本文不编数字。[1][4]

    16
    FAQ

    新手最常问的六个问题

    我没有 GPU，能用吗？
    能。Hermes 本身是 agent 运行时，模型通过 API 调用（Nous Portal、OpenRouter、OpenAI 等），本机只跑 agent 逻辑。只有选择"本地模型"时才对显卡有要求。
    要花多少钱？
    软件免费（MIT）。你只需要为模型 token 付费（用多少付多少），或者订阅 Nous Portal。如果跑在自己电脑上，机器成本是 0；跑在 VPS 上按配置月付。
    Windows 能装吗？
    能，Windows 10/11 属于 Tier 1，用 PowerShell 一行脚本或桌面安装包装。官方提示原生 Windows 上少数功能不可用。
    它会不会把我不该删的东西删了？
    默认 smart 审批模式会对危险命令拦下来问你；定时任务和无人值守入口默认是 拒绝而不是自动批准。要更保险可以切 manual（每步都问），或把终端后端换成 docker 让它只能碰容器里的东西。
    记忆写满了会怎样？
    不会静默丢弃。超过上限时 memory 工具直接报错，agent 需要在同一轮里自己合并或删除条目再重试 —— 设计上就是逼它保持记忆精炼。你也可以直接让它"清理一下过期记忆"。
    能接到微信 / 飞书吗？
    可以。官方 gateway 支持飞书 / Lark、企业微信、微信、钉钉、QQ、Telegram、Discord、Slack、WhatsApp、Signal、Teams、Matrix、邮件等，一条 hermes gateway setup 配置。
